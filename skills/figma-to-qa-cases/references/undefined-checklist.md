# 미정의 항목 체크리스트

[`SKILL.md`](../SKILL.md) 3단계에서 쓴다. 미정의 항목은 기획서에 적혀 있지 않아 TC 의 기대 결과를 정할 수 없는 정보다. 기획자는 알고 있지만 문서에 없는 암묵지가 여기에 해당한다.

## 1. 차단형과 비차단형

| 구분     | 기준                                                     | 처리                                       |
| -------- | -------------------------------------------------------- | ------------------------------------------ |
| 차단형   | 답에 따라 **확인할 동작 자체**가 달라진다: TC 가 생기거나 없어지거나, 절차(누르는 순서, 사전조건)가 바뀐다 | 기획자에게 질문한다 (기획서당 최대 10개)   |
| 비차단형 | 답이 달라도 같은 동작을 같은 절차로 확인하고, 기대 결과의 **값**(문구, 숫자, 형식)만 바뀐다 | 권장값으로 작성하고 목록만 공유한다        |

판정 방법: 선택지 A 와 B 로 TC 를 각각 써 본다고 생각한다. TC 목록이나 절차가 달라지면 차단형, 기대 결과 칸의 값만 달라지면 비차단형이다. 예: "목표 도달 후 +100ml 버튼이 비활성인가"는 A 면 증가 TC, B 면 비활성 TC 라 차단형이다. "날짜를 '목요일'로 쓰나 '(목)'으로 쓰나"는 같은 TC 에서 값만 달라 비차단형이다.

애매하면 차단형으로 둔다. 이유: 비차단형으로 잘못 두면 가정이 틀렸을 때 TC 구조를 다시 짜야 한다. 다만 10개는 상한이다. 넘으면 SKILL.md 3단계대로 영향 TC 가 적은 것부터 비차단형으로 옮긴다.

## 2. 질문 형식

항목 하나에 두 문장을 따로 쓴다. 기획자와 TC 작성자가 보는 정보가 다르기 때문이다.

| 필드       | 읽는 사람  | 쓰는 법                                                                 |
| ---------- | ---------- | ----------------------------------------------------------------------- |
| `question` | TC 작성자  | 무엇이 정의되지 않았는지 한 줄. 예: "목표 도달 후 증가 버튼 동작이 정의되지 않음" |
| `ask`      | 기획자     | "~하면 어떻게 되나요?" 형태의 질문. 기획서를 지적하는 말("없음", "누락")은 쓰지 않는다 |
| `options`  | 둘 다      | 고를 수 있는 답 2~3개. A, B 기호와 "기타"는 쓰지 않는다(스크립트가 붙인다) |
| `where`    | 둘 다      | 기획서 위치. 화면 ID + 주석 번호 + 요소 이름(예: `SCR-03 #8 +100ml 버튼`) |
| `basis`    | TC 작성자  | 권장값의 근거(아래)                                                    |

스크립트가 엑셀 `미정의 항목` 시트에 기획자 전달 문구를 만든다. 근거와 영향 TC 는 넣지 않는다.

```
[SCR-03 #8 +100ml 버튼] 누적 섭취량이 목표(2,000ml)에 도달한 뒤 +100ml 을 누르면 어떻게 되나요?
A. 계속 늘어나고, 컵은 가득 찬 상태로 유지
B. 목표에 도달하면 +100ml 버튼 비활성
C. 기타: (직접 작성)
2026-11-18까지 답이 없으면 A(으)로 TC 를 작성하겠습니다. (U-01)
```

마지막 선택지 "기타: (직접 작성)"은 늘 붙는다. 고르기만 하면 되게 하되, 맞는 답이 없을 때 기획자가 직접 쓸 수 있어야 하기 때문이다.

권장값의 근거는 넷 중 하나로 쓴다.

1. 결정 사전 항목(`D-xx`)
2. 같은 기획서의 다른 화면이나 주석(화면 ID + 주석 번호)
3. 같은 Figma 파일 안 다른 섹션의 비슷한 화면(이미 받은 메타데이터나 스냅샷 안에서 찾는다. 앱 소스 코드는 보지 않는다)
4. 기획서가 이름으로 가리키는 외부 문서(예: "알고리즘_v2 문서 참고"). 내용을 볼 수 없으면 `외부 문서 <이름> (내용 미확인)` 이라고 쓰고, 보고에 그 문서를 사용자에게 요청한다

넷 다 없으면 `근거 없음(기획 결정 필요)` 이라고 쓰고, 왜 그 값을 권장하는지 한 줄 붙인다(예: "과거 달성률이 바뀌지 않는 쪽"). 이유: 근거가 없다는 사실 자체가 기획자가 먼저 봐야 할 정보다. "일반적으로" 같은 말로 근거를 꾸미지 않는다.

## 3. 유형 (이 순서로 찾고, ID 도 이 순서로 매긴다)

| 유형              | 확인할 것                                                                 |
| ----------------- | ------------------------------------------------------------------------- |
| 상태 누락         | 빈 화면(데이터 0건), 로딩, 서버 오류, 오프라인, 저장 실패 화면이 그려져 있는가 |
| 경계값            | 입력 최대 길이와 허용 문자, 목록 0개, 1개, 최대 개수, 중복 입력, 날짜 경계 |
| 전이와 중단       | 뒤로가기, 진행 중 이탈 후 복귀, 백그라운드에서 복귀, 자정 넘김, 연타      |
| 제스처            | 스와이프(화면, 날짜, 바텀시트 닫기), 길게 누르기, 당겨서 새로고침, 핀치. 기획서는 버튼 동작은 주석으로 적어도 제스처는 잘 적지 않는다 |
| 권한과 역할       | 비로그인, OS 권한 거부, 사용자 유형별로 다른 화면                          |
| 정책 수치         | 재시도 횟수, 타임아웃, 노출 기간, 적용 시작일, 정렬 기준                   |
| 기획서 안 불일치  | 기획서끼리 말이 다르다. 주석과 시안(예: 주석 "m월 b일 EEE"(요일 약식) ↔ 시안 "6월 8일 목요일"), 주석끼리, 같은 주석 안의 두 줄(예: "변경사항 있을 시 활성화" ↔ "입력값이 있을 시 활성화"), 화면끼리 같은 요소의 문구. 권장값은 시안 쪽(시안이 없으면 더 구체적인 줄). 차단형 여부는 1장 기준으로 판정한다 |

- 화면 사이 연결(`arrows.json` 의 화살표, 주석의 "~로 이동")이 없는 버튼은 "이동 위치 없음"으로 상태 누락에 넣는다.
- 다른 섹션 화면으로 이동하는 주석(`[SCR-12]로 이동`)은 미정의 항목이 아니다. TC 는 이동했는지만 확인하고, 이동한 화면 내용은 그 섹션을 다룰 때 쓴다.
- 항목이 0개인 유형은 보고에 "해당 없음(이유)"으로 적는다. 예: 권한과 역할 — 기획서에 로그인 이후 화면만 있어 판단 근거 없음.
