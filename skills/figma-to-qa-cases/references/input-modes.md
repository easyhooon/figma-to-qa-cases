# 입력 모드: MCP 와 PDF

## 1. 모드 고르기

| 모드  | 입력                         | 언제                                                                    | MCP 호출       |
| ----- | ---------------------------- | ----------------------------------------------------------------------- | -------------- |
| `mcp` | Figma 링크                   | Figma dev seat 등 MCP 호출 한도가 충분할 때                             | 화면당 2회 + α |
| `pdf` | Figma 메타데이터 + 섹션 PDF | seat 없는 계정. 화면마다 MCP 를 부르면 한도를 바로 넘는다               | 1회            |

어느 모드든 결과는 같은 스냅샷 폴더(`<snap>`)에 저장하고, 2단계부터는 스냅샷만 읽는다. dev seat 이 있는 사람이 스냅샷을 만들어 폴더째 넘기면 seat 없는 사람도 이후 단계를 돌릴 수 있다.

## 2. `mcp` 모드

호출 수를 아래 순서로 최소화한다.

1. `create_session` 으로 파일 세션을 연다.
2. `get_metadata` 1회로 링크 노드 아래 프레임 목록(ID, 이름, 좌표)을 받아 `<snap>/metadata.xml` 에 저장한다.
3. 범위를 확정한다. 범위 밖 프레임은 더 읽지 않는다.
4. 범위 프레임마다 `get_screenshot`·`get_design_context` 를 한 번씩만 호출해 저장한다.
5. `get_comments` 로 댓글을 읽는다. 댓글의 결정은 기획서 내용으로 친다.
6. 한도 오류가 나면 멈추고, 저장된 것과 남은 프레임을 알리고 `pdf` 모드로 이어 갈지 묻는다.

## 3. `pdf` 모드 (MCP 1회 + PDF 1개)

### 왜 PDF 인가 — 사용자에게 내보내기를 요청할 때 함께 설명한다

- **할당량을 쓰지 않는다.** PDF 내보내기는 Figma 앱 기능이라 MCP 호출이 아니다. 화면 단위로 나눠 내보내도 0회다.
- **글자를 원문 그대로 얻는다.** Figma PDF 는 글자를 실제 텍스트로 넣어 `pdftotext` 로 뽑힌다. 기대 결과 문구는 Figma 문구 그대로여야 하므로 이미지 판독보다 정확해야 한다.
- 다른 형식이 아닌 이유
  - PNG/JPG: 글자를 이미지에서 읽어야 해서 작은 한글을 잘못 읽을 수 있다. PDF 로 내보낼 수 없을 때만 3x 배율로 받는다. 보기 권한(read only)이어도 보통은 PDF 로 내보낼 수 있고, 파일 소유자가 공유 설정에서 보기 권한 사용자의 복사와 내보내기를 꺼 둔 경우에만 막힌다.
  - SVG: 설정에 따라 글자가 외곽선(path)으로 바뀌어 읽을 수 없다.
- MCP `get_metadata` 1회는 그대로 쓴다. 메타데이터에는 화면 안의 문구가 없지만(화면 이름·주석 제목만 있음) 프레임 ID·이름·좌표가 있어서, PDF 글자를 어느 화면에 붙일지 정하는 기준이 된다.

### 절차

1. 메타데이터를 `<snap>/metadata.xml` 로 준비한다.
   - 사용자가 `get_metadata` 결과를 저장해 둔 파일을 주면 그 파일을 `<snap>/metadata.xml` 로 복사한다. MCP 를 부르지 않는다.
   - 없으면 사용자에게 Figma 링크를 받아 `get_metadata` 1회로 저장한다. 페이지 전체 링크여도 된다(섹션은 3번에서 이름으로 고른다). 결과가 커서 파일로 저장되면 JSON 의 `text` 값을 꺼내 저장한다.
2. 사용자에게 범위 섹션을 통째로 PDF 로 내보내 달라고 한다(섹션 선택 → 오른쪽 Export → PDF). 위의 "왜 PDF 인가"를 함께 설명한다. 받은 PDF 를 `<snap>/` 에 복사한다.
3. 화면별로 글자와 이미지를 나눈다.
   ```
   node <skill>/scripts/figma-pdf-text.mjs <snap> --pdf <snap>/<섹션>.pdf --section "<섹션 이름 또는 노드 ID>"
   ```
   생기는 파일
   - `frames.json`: 화면 묶음마다 글자 줄. `screen: true` 는 화면 ID(`[SCR-03]` 형태)가 있는 묶음이고, 섹션 제목 배너 같은 묶음은 `false` 다. 영역마다 `kind`(제목, 시안, 주석)가 붙는다.
   - `frame-<화면 ID>.png`: 화면 묶음 이미지(2배율).
   - `arrows.json`: 섹션에 그려진 화살표의 양 끝이 어느 화면, 어느 영역에 닿는지. `shape` 는 직선(`straight`)과 ㄱ자 꺾은선(`bent`), `resolved: true` 면 양 끝 화면이 하나로 정해진 것이다. 방향(출발과 도착)은 이미지에서 확인한다. 기획서는 출발 쪽에 점을 찍는다. 주석의 "tap 시 [화면 ID]로 이동"과 맞춰 보면 확실하다.
   - 출력의 "(프레임 밖)" 줄 수가 많으면 섹션 이름이 틀렸거나 PDF 가 다른 섹션이다. 사용자에게 확인한다.
   - "⚠️ 화면 ID 를 찾지 못했는데 글자가 많은 묶음"이 나오면 화면을 놓친 것일 수 있다. `metadata.xml` 에서 그 묶음 안에 `[화면 ID]` 글자가 있는지 확인한다. 상태별 시안 패널(예: "[키 정보 없는 경우]")처럼 화면이 아닌 묶음도 있다. 화면이 아니면 근처 화면 주석의 근거로만 쓴다.
4. 화면마다 `frames.json` 과 이미지를 **둘 다** 본다.
   - 주석(`kind: 주석`) 글자는 Figma 글자 조각 때문에 띄어쓰기가 깨지거나 줄 순서가 섞인다(예: `타 이 틀`).
   - 시안(`kind: 시안`)과 제목 글자도 깨질 수 있다(예: `1 000 ml` 과 따로 떨어진 `,`, `[HL-02-8 ]`).
   - 그래서 의미는 텍스트로 잡되, 따옴표로 옮기는 문구와 숫자는 모두 이미지로 확인한다.
   - 둘이 다르면 이미지를 따른다. 이미지는 Figma 가 그린 그대로다.
5. PDF 에는 프로토타입 연결과 댓글이 없다. 화면 이동은 `arrows.json` 의 화살표, 분기 박스, 주석만 사실로 치고, 나머지는 "이동 위치 없음" 미정의 항목으로 둔다. 보고에 "댓글 미반영"이라고 적는다.

### 시범 실행 기록

- 2026-11-16, 화면 3개짜리 섹션(3747×12526pt) PDF 1쪽: PDF 좌표와 metadata 좌표가 1:1 로 맞음. 글자 줄 166개 중 프레임 밖 0개. MCP 1회.
- 단어 좌표로 줄을 직접 다시 만드는 방식은 실패했다(Figma 자간 때문에 띄어쓰기가 사라지고 주석 줄이 섞임). `pdftotext` 의 줄 단위를 그대로 쓴다.
- 2026-11-16, 체중 기록 섹션(화면 8개, 5048×12526pt): 화면 ID 가 한 단계 깊은 바텀시트 4개를 화면으로 못 찾던 문제, ㄱ자 화살표 끝이 대상 화면 약 60pt 앞에서 끝나 끝점을 못 찾던 문제를 고쳤다. 고친 뒤 화면 8개, 화살표 6개 모두 확정.
- 2026-11-16, 같은 섹션으로 새 에이전트가 전체 주기 실행: 시안 글자도 깨지는 것, 배너가 화면으로 잡히는 것, 화살표가 출력되지 않는 것을 확인해 스크립트에 화면 구분, 영역 종류, `arrows.json` 을 추가했다.
