# 기획서 공백 체크리스트

[`SKILL.md`](../SKILL.md) 3단계에서 쓴다. 기획서에 적히지 않아 TC 를 쓸 수 없는 정보를 찾는 기준이다.

## 1. 차단형과 비차단형

| 구분     | 기준                                          | 처리                                        |
| -------- | --------------------------------------------- | ------------------------------------------- |
| 차단형   | 답에 따라 TC 의 절차·기대 결과·개수가 바뀐다  | 기획자 질문으로 보낸다 (기획서당 최대 10개) |
| 비차단형 | 답이 달라도 TC 구조는 같고 문구·수치만 바뀐다 | 권장값으로 처리하고 목록만 공유한다         |

애매하면 차단형으로 둔다. 이유: 비차단형으로 잘못 두면 가정이 틀렸을 때 TC 구조를 다시 짜야 한다.

## 2. 질문 형식

```
[G-07] 로그인 › 비밀번호 5회 오류 시 동작이 없음
근거: 노드 12:345 "Login/Error" — 오류 문구만 있고 횟수·잠금 정책 없음
영향: TC 4개
  A (권장) 5회 실패 시 30분 잠금 + 안내 문구 — 근거: 현재 서버 정책
  B 잠금 없이 문구만 노출
  C 기타: ____
답이 없으면 11/20 에 A 로 확정
```

- 권장값의 근거는 셋 중 하나로 쓴다: 결정 사전 항목, 기획서의 다른 화면·주석(화면 ID + 주석 번호), 같은 앱의 비슷한 기존 화면. "일반적으로" 같은 말로 근거를 꾸미지 않는다.
- 셋 다 없으면 `근거 없음(기획 결정 필요)` 이라고 쓰고, 왜 그 값을 권장하는지 한 줄 붙인다(예: "과거 달성률이 바뀌지 않는 쪽"). 이유: 근거가 없다는 사실 자체가 기획자가 먼저 봐야 할 정보다. 수분 기록 시범에서 공백 10개 중 2개가 이 경우였다.
- 선택지는 2~3개. 기획자가 고르기만 하면 되게 한다.

## 3. 공백 유형 (우선순위 순)

| 유형        | 확인할 것                                                              |
| ----------- | ---------------------------------------------------------------------- |
| 상태 누락   | 빈 화면(데이터 0건), 로딩, 서버 에러, 오프라인 화면이 그려져 있는가    |
| 경계값      | 입력 최대 길이·허용 문자, 목록 0개/1개/최대 개수, 중복 입력, 날짜 경계 |
| 전이와 중단 | 뒤로가기, 진행 중 이탈 후 복귀, 백그라운드→포그라운드, 중복 탭(연타)   |
| 권한과 역할 | 비로그인, OS 권한 거부, 사용자 유형별로 다른 화면                      |
| 정책 수치   | 재시도 횟수, 타임아웃, 노출 기간, 캐시 유지 시간, 정렬 기준            |

- 전이와 중단은 프로젝트에 백그라운드·포그라운드 점검 문서가 있으면 함께 본다.
- 기획서 화면 사이에 연결(화살표·프로토타입 링크)이 없는 버튼은 "이동 위치 없음" 공백이다.
- **주석과 시안 불일치**: 주석의 규칙과 화면 시안이 다르면 공백이다(예: 주석 "m월 b일 EEE"(요일 약식) ↔ 시안 "6월 8일 목요일"). 권장값은 시안 쪽으로 두고 비차단형으로 분류한다.
- 다른 섹션 화면으로 이동하는 주석(`[HL-02-118]로 이동`)은 공백이 아니다. TC 는 이동했는지만 확인하고, 이동한 화면 내용은 그 섹션을 다룰 때 쓴다.
